# 사주 계산 엔진 — 판정 기준과 근거

`packages/saju` 의 계산 규칙을 정리한 문서다. CLAUDE.md 5-1, 5-2, 5-8 을 구현하면서 문서에 없던 세부 기준을 여기서 확정했다.
기준을 바꾸면 이 문서와 테스트를 함께 고치고 전체 테스트를 다시 돌린다.

## 1. 판정 기준

| 항목 | 기준 | 근거 |
|---|---|---|
| 연주 | 출생 순간이 그해 **입춘 순간** 이후면 그해 | CLAUDE.md 5-1 |
| 월주 | 직전 **절(節) 순간**의 월지 + 연간에 따른 연두법 | CLAUDE.md 5-1 |
| 절입 비교 | **UTC 절대 순간**끼리 비교. 지방시 보정을 하지 않는다 | 절입은 태양이 특정 황경에 닿는 천문 사건이라 어디서 태어났든 같은 순간이다. 시계 보정은 그 순간을 바꾸지 않는다 |
| 일주·시주 | 출생지 **지방평균태양시**(UTC + 경도 × 4분)로 판정 | CLAUDE.md 5-1 "동경 135° 대비 경도 보정". 문서의 기대값(안동 09:00 → 약 08:35)과 일치 |
| 날짜 경계 | 지방시 **자정** | 일주는 지방시 날짜를 따른다. 예: 서울 00:10 출생은 지방시로 전날 23:37 이므로 전날 일주 |
| 밤 11시~자정 | 일주는 **그날**, 시주는 **다음 날 일간의 子시** (야자시) | CLAUDE.md 5-1 "자시도 그날로". 일주를 그날로 두는 학파(야자시·조자시 구분)에서는 23시대 시주에 다음 날 일간의 子시를 쓰는 것이 일반적이다. 예: 戊午일 23:30 → 시주 甲子 |
| 시지 경계 | 子 23:00~01:00, 이후 2시간 단위 (지방시) | 표준 |
| 균시차 | 판정에 **쓰지 않음**. 참고값(진태양시)으로만 계산하고, 균시차를 넣으면 일주·시주가 달라지는 경계 출생자에게 안내 | CLAUDE.md 기대값이 경도 보정만 한 값이다. 국내에서 흔히 말하는 '약 30분 보정'도 경도만 보정하는 방식이다 |
| 서머타임·표준시 변경 | 당시 벽시계 시각을 UTC로 바꾼 뒤 위 규칙 적용. 1954-03-21 ~ 1961-08-09 의 UTC+8:30 표준시도 자동 반영 | IANA tzdb (아래 3절) |
| 없던 시각·두 번 있던 시각 | 시계를 당겨 없던 시각은 전환 전 오프셋으로, 되돌려 두 번 있던 시각은 앞선 순간(서머타임 쪽)으로 해석하고 안내 | ECMAScript Temporal 의 'compatible' 규칙과 같음 |
| 시간 모름 | 시주 없이 6글자. 일주는 입력한 날짜 그대로 | CLAUDE.md 5-1 |
| 시간 모름 + 절입일 | 연주·월주를 정하지 않고 **두 후보를 함께 반환** (`status: 'needs_time'`) | 추측하지 않는다. 화면(2단계)에서 대략의 시간을 묻는다. 세운 편지는 일간만 쓰므로 영향이 없다 |
| 절입 근접 안내 | 절입과 30분 이내면 안내 | 출생 시각 기록의 반올림, 만세력 간 1분 내외 차이 |
| 지원 범위 | 양력 1920-01-01 ~ 2050-12-31 출생 | 음력 변환 데이터가 2050년까지다 |
| 출생지 | 국내 시·군·구 236곳. 특별·광역시는 "(구 모름)" 항목도 둔다 | 경도 0.1° = 24초라 시·군 단위 정밀도면 충분하다 |

### 세운 (CLAUDE.md 5-2)

| 항목 | 기준 |
|---|---|
| 기간 | [기준일 00:00, 다음 생일 00:00) 한국 시각. 기준일은 포함하고 생일 당일은 제외한다 (편지가 도착하는 날이 생일이므로) |
| 차지 일수 | 입춘 **시각**까지 정밀하게 나눠 비교한다 |
| 동률 | 뒤의 해 (편지를 쓰는 '미래의 나'가 서 있는 해). 분 단위까지 같은 경우라 실제로는 거의 생기지 않는다 |
| 기간이 세 해에 걸칠 때 | 가장 긴 해 |
| 조합 순서 | "하나 버거움 + 하나 편함"이면 버거운 축을 먼저 반환 |

### 연결 규칙 (CLAUDE.md 5-8)

- 점수는 0.5 단위라 내부적으로 2배한 정수로 계산한다. 경계값(0.5, 0.2)에서 부동소수 오차가 생기지 않는다.
- "왼쪽 + 오른쪽 < 2 → 최대 약간"은 합이 정확히 2이면 적용하지 않는다.

## 3. 데이터와 출처

- **표준시·서머타임** (`src/data/korea-time.ts`): IANA tzdb `Asia/Seoul`, Rule `ROK`. tzdb가 인용한 원자료는 관보, 대통령령 제876호, 법률 제676호, 국가기록원 관보 이미지다.
  - 알려진 불확실성: 1950~1951년(한국전쟁 중) 서머타임 시행 여부. tzdb 주석에 "전쟁 중 중단"이라는 다른 보고가 있지만, 현행 규칙은 시행으로 본다.
- **출생지 좌표** (`src/data/birthplaces.ts`, `scripts/gen-birthplaces.mjs` 로 생성): 통계청 SGIS 행정동 경계(공공누리 제1유형)를 vuski/admdongkor 가 가공한 ver20250701 판(CC BY 4.0)을 쓴다. 대표 좌표는 행정동 폴리곤의 면적 가중 중심이다.
  - **출처 표시 의무가 있다.** 서비스 화면(예: 이용약관 하단 또는 오픈소스·데이터 고지 페이지)에 "통계청 SGIS 행정구역 경계, vuski/admdongkor (CC BY 4.0)"를 표기해야 한다.
  - 2026년판은 광주·전남이 '전남광주통합특별시'로 합쳐져 있다. 출생 당시 지명으로 고르는 사용자를 위해 통합 전 판을 썼다.

## 4. 검증 현황

| 대상 | 방법 | 결과 |
|---|---|---|
| CLAUDE.md 검증 완료 케이스 | `test/golden.test.ts` | 원국, 글자표, 축 점수, 세운 매핑 모두 일치 |
| 절기 시각 1920~2050 (1,572건) | lunar-javascript(寿星 알고리즘)와 대조 | 최대 차이 52초 |
| 일주 1920~2050 매일 (47,848일) | 한국 음력 라이브러리의 일진과 대조 | 전부 일치 |
| 연주·월주 | 무작위 시각 2만 건(개발 중 20만 건)을 lunar-javascript 팔자와 대조 | 전부 일치 |
| 서머타임 표 | Node ICU(tzdb 2025b)와 1912~2050 매일 + 전환 시각 대조 | 전부 일치 |
| 테스트의 민감도 | 야자시 규칙, 0.5 경계, 서머타임 날짜를 일부러 틀리게 바꿔 실행 | 모두 테스트 실패로 잡힘 |

`test/` 의 경계 케이스(절입 직전·직후, 야자시, 서머타임 등)는 **회귀 테스트**다. CLAUDE.md 의 "검증 완료" 케이스와 달리 외부 만세력과 대조하지 않았다.

## 5. 출시 전 사람이 확인할 것

1. **국내 만세력 2곳과 대조** (CLAUDE.md 5-1 요구). 아래 케이스를 넣어 연·월·일·시주를 비교한다. 만세력 설정은 "경도 보정 사용, 야자시 사용"으로 둔다.
   - 2000-01-01 23:50 서울 → 戊午일 甲子시 (야자시)
   - 2000-01-02 00:10 서울 → 戊午일 甲子시 (지방시로 전날)
   - 1996-02-04 22:00 / 22:30 안동 → 乙亥년 己丑월 / 丙子년 庚寅월 (입춘 22:08)
   - 1987-07-01 12:00 서울 → 巳시 (서머타임)
   - 1960-01-01 12:00 서울 → 午시 (UTC+8:30 시절)
   - 음력 2017 윤5월 1일 → 양력 2017-06-24
   - 만세력과 다르면 어느 기준 차이인지(야자시 처리, 경도 보정 여부, 서머타임 반영 여부) 확인한 뒤 결정하고 이 문서를 고친다.
2. **절기 시각 표본 대조**: 한국천문연구원 천문우주정보(astro.kasi.re.kr) 절기 시각과 몇 해를 분 단위로 대조한다.
3. **1950~1951년 서머타임**: 국가기록원 관보로 시행 여부를 확인한다.
4. **출생지 데이터 출처 표시**를 화면에 넣는다 (2단계 이후).
